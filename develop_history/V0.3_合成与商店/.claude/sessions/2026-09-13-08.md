## 做了什么

1. **规则形状换了**（服务端）：一条规则 = 对局模式 + 一串 and/or 条件。
   - `shopcfg`：`CARD_JOIN_*` / `CARD_SCOPE_PREFIX_ZH` / `CARD_PHRASES` /
     `CARD_ENUM_METRICS` / `CARD_METRIC_STAT` / `CARD_METRIC_UNIT` /
     `CARD_SAMPLE_METRIC` / `CARD_GRANT_COUNT` / `MAX_CARD_CONDITIONS`；
     新指标 `won`「本局结果」；`accuracy` 改名「命中率」+ 单位 `%`。
   - `describe_card_rule` 重写成一句完整的话（`with_tail=False` 给提示框）。
   - `_validate_card_conditions` 接管全部护栏；`SCHEMA["cards"]` 换成
     `type: "conditions"` 的子字段表（前端照它画弹窗）。
   - `cards.py`：`eval_conditions` / `_condition_holds` / `card_progress`；
     `due_grants` 返回「新的计数器基准」而不是「里程碑目标」。
   - `account_store`：新字段 `card_bases`，`apply_battle` 的
     `card_targets` → `card_bases`。
2. **管理页重排**（`admin.html` / `admin.css` / `admin.js`）：
   一行四格 + 两个设置弹窗 + 一个进度弹窗；工具条只剩分组切换和一颗钮。
3. **前后端对词的拦网** `test_cardtext.py`（node 跑真的 `admin.js`）。
4. **达成进度**：`GET /admin/api/cards/progress`，两个入口一发接口。
5. **三条交互返工**（用户试出来的，见 D114）。
