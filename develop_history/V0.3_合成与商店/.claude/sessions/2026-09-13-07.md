# 2026-09-13 会话 07 —— 称号卡片掉落页重构（D110 / §106）

## 用户点的题

看了会话 42（同一天）的成果后：「统计指标的内容太多太复杂了，很多内容都可以
通过其他条件排列组合实现……**无论怎么设置，总有一个必选的专属指标，既然这样，
还单开一个设置页面干什么**」。举的例子就是「完美胜利（零死亡获胜）」——
本该是「死亡次数为 0 + 只有胜利才给」。

拍板四条（`AskUserQuestion`）：① 一条规则仍只有**一个条件** + 胜利开关（不做多条件 AND）；
② 指标 22 → 16，**连命中率一起砍**；③ 三段分组 + 藏掉不适用的格；
④ 这一版还没上线（云上没有 `cards.json`、存档里没有 `battle_stats`）。

## 两个坑（都写进 D110 / §106 了，这里只标位置）

1. **`cards.due_grants` 里那一行 `max(1, threshold)`** —— 判定层自己又夹了一次
   下限，不改就把 `eq 0` 悄悄提成 `eq 1`。全套里最容易漏的一行。

## 验收手法：**离线渲染台**（这次新造的，下次还能用）

GM 登录要输密码，agent 不做这件事 ⇒ 改成：
把真的 `admin.js` + `admin.css` 拷进 scratchpad，`cat.json` 由 Python 直接从
`shopcfg.SCHEMA` / `card_metrics_for_admin()` / `default_cards()` 导出，
一个 `lab.html` 把 `fetch('/admin/api/...')` 挡掉（admin.js 顶层会自己去要 session）、
`CAT = {}` 手动填上（它的初值是 `null`）、直接调 `cardRow()` 画进一个 `#cfgList`。
`python -m http.server` 起在 127.0.0.1（⚠ `file://` 不跑 JS）。

这么验能看到真实像素和真实联动，还能塞几条**故意配歪**的规则专门验
「不适用的格子怎么画」。⇒ 以后改管理页版式都可以这么来，不用登录。
