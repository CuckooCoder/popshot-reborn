用户点的题两件：① 双击 `tools\build-pack.bat` 输出乱码；② 之前留下的称号韩文没翻译，
顺便找找还有没有别的没翻 / 翻错的。用户后来追加：任务 / 对战的**地图名**、**商城角色名**

## ① 乱码

查出来不是 V0.2 §135 那个「bat 里的中文被拦腰截断」——`build-pack.bat` 早就是纯 ASCII。
真凶是 `build-common.ps1:1002` 的 `| Out-Host`（会话 07 为「输出混进返回值」加的）：
一建管道 CPython 就从 `WriteConsoleW` 掉到 `GetACP()`=cp936，而 `chcp 65001` 的宿主按
utf-8 解 ⇒ 一个汉字碎成两个替换符。所以窗口里**只有 python 打的行乱**，
PowerShell 自己 `Write-Host` 的中文是好的。

改：`pkn.py` 的 `reconfigure` 补 `encoding="utf-8"`（原来只有 `errors`，那治「编不出来」
不治「编错了」）+ `build-common.ps1` 顶部钉 `[Console]::OutputEncoding`。
守卫 `test_packdirs.PackToolEncodingTests` 两条。

## 怎么改的 UTF-16 文件

Read/Edit/Write 工具读 UTF-16LE **行号和内容全错位**、Write 还会按 UTF-8 落盘毁文件；
Git Bash heredoc 又按 CP936 落盘。⇒ 中文字面量放 UTF-8 的 `.py` 里，Python 二进制读写、
自己管 BOM 和行尾。★ `ShopItem-Chn.ini` 是**纯 LF**，同目录其余全是 CRLF —— 用 text mode
写会把 9532 行全翻成 CRLF。所以全程「整段字符串替换」，不 splitlines。

护栏（都真的挡住过东西）：每条新 key 必须在它声称的源文件里真的存在（`.ui` 先做 XML
反转义 —— 第一次跑就是被 `< 퀘스트 정보 >` 拦下来的）、不许和已有 key 重名、译文里不许
还有韩文、`%d/%%/%s` 格式符必须一一对应。

## 踩到的

* UTF-16 文件的 diff：`git diff` 必判 binary（每个 ASCII 字符带一个 `\x00`），`--text` 也没用，
  `.gitattributes` 的 `-text` 管的是 eol 转换不管 diff。⇒ 用 `git show HEAD:<path>` 取基线
  （**不加 `text=True`**，要原始字节）+ `difflib` 自己比。
* 拿 Python 改脚本时用正则把 `raise SystemExit(...)` 批量换成 `say(...)`，
  **把 5 处硬中止降级成了警告**。靠「打印错误的下一行必须是 raise」这条规则补回来的。
* `TipMsg-Chn.ini` 结尾三个空行是**原版就有的**（和 HEAD 逐字节相同），不是改坏的 ——
  我那条「结尾多了空行」的断言写成了绝对判据，应该和基线比。
