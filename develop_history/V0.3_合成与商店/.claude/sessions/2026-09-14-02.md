# 2026-09-14 会话 02 —— 把运营调好的卡片条件 / 称号配方回填成出厂值

用户点的题：「最近刚加了成就卡片和称号合成的功能，我对加上的这些卡片获取条件和
称号合成配方刚手动修改过，请你把这两部分现在的状态作为默认值，写入模板。」

结论和理由在 **D116**，这里只记「做了什么 / 怎么验的 / 留了什么」。

## 动了两个文件

| 文件 | 干了什么 |
|---|---|
| `server/shopdefaults.py` | `CARD_RULES`（17 条获得条件）+ `TITLE`（17 条称号配方）照 `server/data/cards.json` / `recipe.json` 逐条改过来；`_WEAPON_CARD_KILLS` 从三档的 dict 变成一个数（用户把三档拉平了）；两张表上面的注释跟着重写 |
| `server/test_cards.py` | 三条钉着旧值的用例：幸运卡那条改成「36 且胜利 **或** 累计 166」（多了第三条条件）、说明文那条 `30` → `36`、提示框软上限 `40` → `64` |

**盘上的 `server/data/*.json` 一个字节没碰**（它是运营数据，改模板不该动它）；
客户端、管理页、服务端逻辑也都没动。

## 怎么验的

```python
shopdefaults.default_cards()["rules"] == json.load(open("data/cards.json"))["rules"]   # True
```

称号那 17 条比 `result` / `listed` / `cost` / `materials`，也全等。
★ **连键序和条件先后都一样** —— 条件是「从上往下结合、没有括号」（D111），
顺序换了意思就变了，所以这一条要按整个 list 比，不能按集合比。

顺手把六份运营配置整份对了一遍（不是只对这两块）：

| 文件 | 和模板 |
|---|---|
| `cards.json` / `recipe.json` | ✅ 回填后**整份**一致（139 条配方里那 122 条非称号的，用户一条没动） |
| `shop.json` / `drops.json` / `rewards.json` | ✅ 一致 |
| `items.json` | ⚠ 差 2 条：`560001 [完美胜利者]` 等级 10、`560007 [队内间谍]` 等级 5（模板里称号一律 1 级） |
| `sell_price.json` | ⚠ `equip_percent` 盘上 100、模板 95 |

两套运行时（3.14 / 3.8）各跑一遍 `server/run_tests.py`：**3507 项全绿**。

★ 回完之后用户**又调了一次**：`560004 [幸运幸存者]` 从 166 张改成 **666 张**
（金币仍 111666）⇒ 表里改一个数、`TITLE` 上面那段注释跟着改，判据重跑一遍
`recipe == True`，两套运行时再全绿一遍。**回填不是一锤子买卖**，下次先跑判据
看差在哪，别照着上一轮的印象改。

## 留了什么

* 上面那两处 ⚠ **没动** —— 用户点的是「卡片获取条件」和「称号合成配方」两块，
  称号的**穿戴等级**和**卖出折扣**不在里面。已经报给用户，等一句话。
* `60004` 的条件念出来 56 个字，提示框第 1 段那 6 行里要占 3 行（D116④）。
  **实机没看过这一句长什么样** —— 提示框是客户端自己折行的。
