# 2026-09-14 会话 06 —— `server.out` 按天切分 + 日志行补日期

用户点的题：「以前我改过一次，让游戏 log 自动按日期分割，并且自动删除超过设定
天数的 log。但是我发现还有几个 log 文件没有按日期分割，比如 `server.out`。
我从云服务器取了最新的 log 放在 `bug调查\挂机识别测试`，里面的 `server.out`
单文件已经达到了 900MB 上下。……里面的 log 内容也没有记录日期，只有时间，
导致查问题的时候不好判断到底是哪天的 log。」

结论和理由在 **§113 / D122**，这儿只记流水账。

## 先量：940 MB 是怎么攒出来的

```text
bug调查/挂机识别测试/logs - server/server.out   940,887,811 字节（2 天）
                                    online-20260912.log / online-20260913.log ← 这两个切了
```

965 万行、平均 97.5 字节/行。`log_retention_days = 3` 一直开着，一次都没清到它：
`logcleanup` 判据是 **mtime**，而**一直在写的文件 mtime 永远是刚才**。
`online.log` 没这毛病，因为 `eventlog` 跨零点把昨天那份改名走了。

⇒ 真正缺的不是「清理」，是**切分**。而 `server.out` 是启动脚本重定向出来的，
那个句柄不归 Python ⇒ 只能改成「让 Python 自己开这个文件」。

## 踩到 / 想清楚的

* **`DaySink.close()` 一开始写成「只 flush 不关」**（照 `sys.__stdout__` 的
  想法），结果单测的临时目录在 Windows 上删不掉 —— `install()` 把流挂进了
  `atexit`，对象永远不回收，句柄永远不放。改成**真关、下次写自己重开**：
  两头都要（放句柄 + `sys.stdout` 被谁关一次不能就此报废）。
* **为什么必须多出 `*-boot.*` 这一对**：不能让两个写手抢同一个文件，而
  重定向又不能不要 —— `install()` 之前那一段（`SyntaxWarning`、import 当场
  炸的 traceback）只在那里边，`-WindowStyle Hidden` 下丢了就再看不到。
* **加日期的代价量过**：+11 字节/行 = **+11.3%**（按云端那份的 97.5 字节/行）。
  接受，因为总量现在是有界的。
* **文件名带日期解决不了用户的问题** —— 排查时贴出来的恰恰是单独几行，
  文件名跟不过去。所以日期必须进行里。
* ★ **差点把日志写进发出去的包里**：`daylog` 按包根算路径，而打包自检会把包里的
  服务端真跑一遍 ⇒ 包里那个本该空着的 `logs\` 会躺着一份启动日志。
  加了 `--no-day-log`（和 `--no-online-log` 那三个是同一类），
  并让 `Assert-PackageDataClean` 跟着验「`logs\` 必须是空的」——
  光加开关不算完，这是 D7 那条教训。

## 第二轮（用户看完之后点的三件事）

### 1. 「一直不关的服务端，过零点会切吗？」—— 会

判据在 `DaySink.write()` 里，**每写一行比一次**「这个句柄是哪天开的 vs 现在
是哪天」，没有任何定时器。但「我读代码觉得对」不算验过 —— `DaySink` 加了
`_localtime` 注入点（同 `atomicfile` / `crashwatch`），新增两条：

* `test_a_process_that_never_restarts_still_rolls_at_midnight` ——
  真 `asynclog` 写线程 + 真 `sys.stdout` 替换，**一次不重开**，只把钟从
  23:59:50 拨到 00:00:10。昨天那行必须在 `server-20260913.out`、今天那行
  必须在 `server.out`，两边都不许串。
* `test_a_day_with_nothing_to_say_does_not_leave_an_empty_file` ——
  空转 3 天再写也切得对，中间那几天**不留空文件**。

### 2. `updater.log` 也切，并重编

`updater/src/log.c` 加 `rotate_if_stale()`：开文件前看盘上那份是哪天写的，
跨天就 `MoveFileW` 成 `updater-YYYYMMDD.log`。命名规则抽成
`log_dated_name()` 暴露到 `log.h`，`selftest` 加 5 条钉住（和
`apply_is_protected` 一个套路）。`build.bat` 跑通，闸门 **92 checks, 0 failed**，
`game_patched\BsPatcherChn.exe` 已重编（用户说放下一个版本一起发）。

沙箱运行时验证（`POPSHOT_UPDATER_NOUI=1` 无头跑三次）：

```text
第 1 次         logs/updater.log 新建
把 mtime 拨到昨天
第 2 次         updater-20260913.log（mtime 保住在昨天）+ 新的 updater.log
第 3 次（同一天） 只追加，start 出现 2 次，不新建
```

★ 踩到：`small` **不能**当变量名 —— `windows.h` 的 `rpcndr.h` 里
`#define small char`，报出来是莫名其妙的
`C2628: "wchar_t"后面接"char"是非法的`。

### 3. `serverctl.sh` 真跑一遍

这台机器**没有 WSL 发行版、也没有 docker**（`wsl -l -v` 直接吐帮助）。
所以搭了个「服务端包」形状的临时目录：

```text
<sandbox>/tools/serverctl.sh   + server/（整份拷贝，删掉 __pycache__ 和 data）
          config/server.config + logs/ + BUILD.ver
          bin/python3          ← 一行 shell 垫片 exec 到真 Python
```

★ 坑：`export PATH="$W/bin:$PATH"` 里的 `$W` 是 `C:/…` 形式，Git Bash 的 PATH
认不出来，`command -v python3` 还是找到了 Microsoft Store 那个假货。
要先 `cygpath -u` 转成 `/c/…`。

跑通四条路：`start` ✅ / `stop`（含残留 pidfile）✅ / 端口被占（启动前预检拦住）✅ /
**服务端起来又死掉**（往沙箱的 `app.py` 里植入一个 `raise`）✅ ——
最后这条正是我改动最大的那段，输出：

```text
[启动失败] 端口没起全，下面是日志的末尾：
  --- logs/server-boot.err ---   ← 解释器的 SyntaxWarning（2.3 KB，真接住了）
  --- logs/server.err ---        ← daylog 装好之后抛的 traceback
  --- logs/server.out ---        ← 启动横幅
```

★ 意外收获：本机因为有 `__pycache__`，`server-boot.err` 一直是 0 字节，
差点以为这对文件没用；沙箱里没有 pyc，它**真的**接住了那 2.3 KB 警告。

### 4. `bshook_*.log` 不动（用户拍板）

顺带查清：它**没有**文件行数/大小上限 —— `BSLOG_RING_BYTES` 是 4 MB 的
**内存环**（异步写的内存预算），不是文件上限，磁盘上实测有 29 MB 的单份。
但它本来就不是同一个毛病：文件名带日期、每次运行一份、退出就没人再写
⇒ mtime 冻住 ⇒ 照常被清掉。
